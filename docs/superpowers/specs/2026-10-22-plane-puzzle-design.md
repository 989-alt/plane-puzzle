# 평면 도형 이동 퍼즐 (가칭) — 설계 문서

작성일: 2026-10-22 · 상태: 초안(사용자 승인 대기, 빌더 검토 통과)
자매 앱: 큐브 왕국 건축가 `~/space-puzzle` (라이브 https://989-alt.github.io/space-puzzle/)

## 1. 무엇을, 왜

3~4학년군 수학 「평면도형의 이동」 수업 뒤 학생이 혼자 하는 **평면 조각 맞추기 퍼즐 웹앱**이다. 보드게임 우봉고의 평면판 규칙을 빌린다. 조각을 **밀기·뒤집기·돌리기**로 움직여 판을 빈틈없이 채운다.

- **핵심 학습:** 조각을 움직이기 **전에** "이렇게 뒤집거나 돌리면 어떤 모양이 될까"를 머릿속으로 예측하는 힘. 단계가 오를수록 미리보기를 줄여, 예측 없이는 풀 수 없게 만든다(사용자 결정).
- **형식:** 큐브 왕국과 같은 짜임. 연속 정답에 따라 난이도·점수 배율이 오르고, 첫 접속 때 짧은 조작 안내가 나오며, 틀려도 벌 없이 시간 보너스만 놓친다(사용자 결정: "지금 만든 버전과 같은 형식").
- **배포:** 큐브 왕국에 합치지 않고 **별도 저장소 `989-alt/plane-puzzle`**, GitHub Pages `989-alt.github.io/plane-puzzle`(사용자 결정).

### 근거 성취기준 (2022 개정, curriculum-kr MCP 확인)
- **[4수03-04]**, **[4수03-05]** — 「평면도형의 이동」 소주제(밀기·뒤집기·돌리기). 빌더는 계획 단계에서 curriculum-kr MCP `get_standard`로 원문을 받아 설계 문서 이 절에 붙인다.
- 교과서 용어를 그대로 쓴다: 밀기, 뒤집기(위쪽·아래쪽·왼쪽·오른쪽으로 뒤집기), 돌리기(시계 방향·시계 반대 방향으로 90°, 180°, 270°).

## 2. 목표 · 비목표 · 반목표

**목표**
- 태블릿·크롬북 터치(학생 주력)와 PC 마우스(교사 시연) 모두 1급 지원.
- 버튼 이름과 동작이 교과서 표현과 정확히 같다.
- 단계가 오를수록 "결과를 미리 보여 주던 것"이 줄어든다.
- 정적 파일만, 백엔드 없음.

**비목표:** 교사 대시보드·참여, 멀티플레이, 계정·로그인, 서버·DB·외부 API, 큐브 왕국과의 통합 메뉴.

**반목표 (돌아가도 이러면 실패)**
- 문제 팝업이 게임을 멈추거나 틀렸다고 벌주는 구조. 이동 횟수를 넘겨도 끝까지 풀 수 있어야 한다.
- 조각이 배경 위에 붙은 스티커처럼 떠 보이거나 어수선한 화면(큐브 왕국에서 사용자가 반복 지적).
- 대칭 조각뿐이라 뒤집기·돌리기를 안 해도 풀리는 문제.
- 버튼이 조각을 가려 탭이 엉뚱한 버튼에 맞는 것(큐브 왕국 F 결함과 같은 유형).
- 우봉고 이름·원작 조각·카드·그림 사용. 학생 개인정보 수집(이름 입력칸도 없음).
- 뱀서라이크 장르 요소(금지 지시).

## 3. 대상과 환경
- 3~4학년. 수업 뒤 개별 활동, 교사 개입 없음.
- 가로 16:10 무대. 세로면 "가로로 돌려 주세요"(큐브 왕국과 같음).

## 4. 게임 규칙

### 4.1 판과 조각 (사용자 결정: 정사각형 칸 조각 + 칠교형 삼각형 조각 섞기)
- **격자(제가 정한 것):** 정사각형 칸을 두 대각선으로 4등분한 **삼각 조각칸(사분 삼각형)** 격자. 모든 조각은 사분 삼각형의 집합이다. 이렇게 하면
  - 정사각형 칸 조각(펜토미노·테트로미노류) = 칸마다 사분 삼각형 4개,
  - 칠교형 조각(직각이등변삼각형 작은 것/큰 것, 평행사변형, 사다리꼴 등, 변이 격자선이나 칸 대각선 위) 도 같은 격자에 놓이고,
  - 90° 돌리기·뒤집기 결과가 항상 격자에 맞아 판정이 정확하다.
- 돌리기는 90° 단위만(교과서 범위). 45° 기울어진 칠교 조각은 쓰지 않는다.
- **조각 무늬(제가 정한 것):** 각 조각에 방향이 드러나는 작은 무늬(예: 한쪽 모서리 점이나 화살표)를 넣어, 뒤집었는지 돌렸는지 눈으로 구별되게 한다. 무늬는 판정에 쓰지 않는다.
- 문제 은행 조건: 모든 해답에서 **적어도 한 조각은 뒤집기가, 적어도 한 조각은 돌리기가 필요**해야 한다. 대칭이라 이동이 무의미한 조각은 한 문제에 1개 이하.

### 4.2 조작 (사용자 결정: 교과서 버튼 그대로)
- **밀기:** 조각을 끌어서 옮긴다. 놓으면 가장 가까운 격자 자리에 맞춘다. 이동 횟수에 세지 않는다.
- 조각을 탭/클릭하면 **이동 패널**이 열린다.
  - 뒤집기 4개: 위쪽·아래쪽·왼쪽·오른쪽으로 뒤집기(왼쪽·오른쪽은 같은 결과, 위쪽·아래쪽은 같은 결과 — 교과서가 가르치는 내용 그대로 둔다).
  - 돌리기: 시계 방향 / 시계 반대 방향 × 90°·180°·270°.
  - 버튼 그림은 교과서식 화살표 기호. 버튼 최소 48px.
- 패널은 조각·단서 카드·도구 막대를 가리지 않는 자리에 둔다(큐브 왕국 `ringPlace.js`의 회피 규칙을 옮겨 쓴다).
- 뒤집기·돌리기 버튼 1번 = 이동 1회.

### 4.3 단계 (사용자 결정: 완성 모양 → 조건 단서, 미리보기는 단계별로 줄이기)
| 단계 | 판 단서 | 버튼 누르면 | 비고 |
|---|---|---|---|
| 1 | 판에 조각별 완성 그림(반투명 윤곽)이 보임 | 조각이 즉시 바뀌어 보임 | 잘못 놓은 조각은 붉게(큐브 왕국 1단계와 같음) |
| 2 | 판 바깥 윤곽만 | 즉시 바뀌어 보임 | 조각 3~4개 |
| 3 | 윤곽 + 조각마다 **이동 조건 카드**("이 조각은 뒤집어야 맞아요", "시계 방향으로 돌려야 맞아요") | **결과가 숨겨짐**: 누른 이동이 조각 옆에 카드 줄로 쌓이고, 조각은 원래 모양 그대로 보임. 판에 놓는 순간 쌓인 이동이 차례로 애니메이션되며 결과가 드러남 | 예측 단계 시작 |
| 4 | 윤곽 + **이동 횟수 목표**(해답 탐색기가 구한 최소 이동 수) | 결과 숨김(3단계와 같음) | 목표 이내로 풀면 별 보너스. 넘겨도 계속 풀 수 있음 |

- 3·4단계에서 놓았는데 맞지 않으면 조각은 드러난 결과 모양으로 판 밖 원래 자리로 돌아간다(이제 결과를 봤으므로). 벌 없음.
- 3·4단계에서 숨김 모드로 놓을 때 기준점: 손가락 아래 칸 = 이동 결과 조각의 잡은 칸(빌더가 정밀하게 정함, 잡은 칸이 결과에서 어디로 가는지 계산 가능).
- 3·4단계 이동 카드 줄(제가 정한 것): 맨 끝 카드를 지우는 "되돌리기"와 전체 "처음으로" 버튼이 있다(되돌리기도 이동 1회로 센다). 놓기에 실패하면 줄은 비고, 조각은 드러난 결과 모양이 새 출발 모양이 된다.
- 뒤집기·돌리기는 조각 제자리(조각 가운데 기준)에서 일어난다. 결과가 다른 조각과 겹치면 가장 가까운 빈 자리로 비킨다(큐브 왕국 회전 수정과 같은 규칙).
- 이동 조건 카드는 **모든 해답에서 참인 조건만** 쓴다(어떤 해답에서는 뒤집지 않아도 되면 "뒤집어야 해요" 카드를 붙이지 않음). 4단계 목표 이동 수는 모든 해답 중 최소값.
- 60초 뒤 "쉬운 단서" 버튼: 한 단계 쉬운 단서로 바꾸고 점수 절반(큐브 왕국과 같음). 3·4단계에서는 결과 미리보기를 켜 준다.

### 4.4 점수·진행 (큐브 왕국과 같음)
- 점수 = (100 + max(0, 60 − 걸린 초)) × 연속 배율(1~2연속 ×1, 3 ×1.5, 4~5 ×2, 6+ ×3), 쉬운 단서 쓰면 절반. 4단계 최소 이동 달성 시 별 보너스(빌더가 값 제안).
- 깨끗하게 2번 풀면 다음 단계. 1~4단계.
- 저장은 localStorage(try/catch), 개인정보 없음.

### 4.5 문제 만들기 (큐브 왕국 방식)
- 목표 판 모양을 만들고 조각으로 쪼개는 **거꾸로 만들기**, 시드 고정 생성기로 단계별 40문제를 미리 만들어 JSON으로 넣는다. 런타임 생성 없음.
- 해답 탐색기로 해답 수, 필요한 이동(뒤집기·돌리기 존재), 최소 이동 수를 계산해 4.1 조건과 4단계 목표에 쓴다.
- 단계별 조각 수(제가 정한 것): 1단계 3개(칸 조각), 2단계 3~4개, 3단계 3~4개(삼각형 조각 섞임), 4단계 4~5개.

## 5. 화면 (사용자 결정: 큐브 왕국과 같은 세계관, 평면 판)
- 큐브 왕국과 같은 판타지 일러스트 톤. 판은 **위에서 내려다본 작업대**. 원근 없는 탑뷰라 배경도 탑뷰여야 스티커처럼 안 보인다 → kie.ai gpt-image-2로 같은 화풍의 탑뷰 작업대 배경을 새로 생성(키: `~/docs/.env` `KIE_API_KEY`, 스크립트 `~/.claude/skills/education-pptx/scripts/image_gen.py`).
- 조각은 두께감 있는 나무/보석 타일(그림자로 판 위에 놓인 느낌). 판은 화면 가운데, 조각은 그 둘레 트레이, 화면 밖으로 못 나감.
- 글꼴·버튼·HUD·첫 접속 안내·승리 화면은 큐브 왕국 것을 옮겨 쓴다(Jua·Pretendard vendored).
- 시각 기준: issamGPT AI Mart 게임 수준.

## 6. 기술
- 정적 ES 모듈, 빌드 도구 없음(한글 경로에서 vite 크래시). three.js 쓰지 않음.
- 큐브 왕국에서 가져와 고쳐 쓸 것: `src/core/progress.js`, `storage.js`, `src/ui/*`(화면·HUD·단서 카드), `src/scene/ringPlace.js`의 회피 논리, `tests/e2e`의 Playwright(시스템 Edge) 하네스, 글꼴·`.nojekyll`.
- 새로 만들 것: 사분 삼각형 격자 기하(`core/grid`), 조각 변환(뒤집기 4종·돌리기 6종, 정규화), 판정, 해답 탐색기·생성기, 2D 렌더러, 입력(끌기·탭·패널).
- 테스트: `node --test --test-isolation=none "tests/**/*.test.mjs"` + Edge headless e2e(8GB PC, 한 번에 하나씩). 큐브 왕국처럼 전수 감사 도구(모든 문제가 실제 조작으로 풀리는지, 이동 조건·최소 이동 수가 맞는지)를 처음부터 둔다.
- 철칙 문서 `Downloads\교육용게임_개발철칙.md`를 빌더가 먼저 읽는다.
